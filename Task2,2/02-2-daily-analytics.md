# Л2.2. Агрегирующая аналитика по журналу дней

**Часы:** 0 · **Статус:** дополнительная, для самостоятельного выполнения

По журналу за месяц посчитать бонусы по правилам ниже и вернуть сводку.

Два оформления одних и тех же чисел:

- **A.** Отдел продаж: электроника, одежда, товары для дома.
- **B.** Электроэнергия: ночь, полупик, пик. Ставки, пороги и надбавки — из таблиц варианта A, меняются только имена категорий.

## Данные

Журнал — список словарей за 30 дней. Его порождает скрипт с фиксированным `seed`. В журнале должны встретиться все ветви правил.

```python
sales_data = [
    {"day": 1, "electronics": 1200, "clothing": 800, "home": 450},
    {"day": 2, "electronics": 900, "clothing": 600, "home": 300},
    {"day": 3, "electronics": 1500, "clothing": 1200, "home": 800},
]
```

## Правила

Базовый процент:

| Категория | Процент |
|---|---:|
| Электроника | 15 % |
| Одежда | 10 % |
| Товары для дома | 8 % |

Множитель по объёму категории за день:

| Объём | Множитель |
|---|---:|
| более 1000 | ×1.5 |
| от 500 до 1000 включительно | ×1.2 |
| менее 500 | ×1.0 |

Надбавка за сумму дня, к итоговому бонусу дня:

| Сумма по категориям | Надбавка |
|---|---:|
| более 3000 | +5 % |
| от 1500 до 3000 включительно | +2 % |
| менее 1500 | нет |

## Задание

1. Функция `calculate_advanced_bonus(sales_data)` возвращает:

```python
{
    "daily_bonuses": [...],
    "category_totals": {...},
    "best_day": ...,
    "days_above_average": [...],
    "average_bonus": ...,
}
```

2. Правила — отдельные функции: `category_multiplier(amount)`, `daily_surcharge(total)`, `category_bonus(amount, rate)`. `calculate_advanced_bonus` собирает сводку.
3. Проценты, множители и пороги — данные модуля.
4. Проверить запись: все ключи на месте, значения числовые и неотрицательные, номера дней не повторяются. Некорректная запись — исключение с номером дня и именем поля.
5. Напечатать таблицу «день — бонус по категориям — надбавка — итог» и сводку: лучший день, средний бонус, число дней выше среднего. В таблице суммы с двумя знаками после запятой.
6. В отчёте: как изменится `best_day`, если множитель для объёма более 1000 станет 1.3; почему сумма `category_totals` не совпадает с суммой `daily_bonuses`.

## Требования

- Только стандартная библиотека.
- Функции правил не читают журнал сами: данные приходят параметрами.
- Поведение на пустом журнале описано в docstring.

## Приёмка

- Расчёт одного дня совпадает с ручной выкладкой.
- В таблице отчёта видны все ветви множителей и надбавок.
- Пустой журнал ведёт себя так, как написано в docstring.
